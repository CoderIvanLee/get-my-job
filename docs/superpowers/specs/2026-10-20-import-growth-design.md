# 快速归档与跨岗位成长计划

用户要求减少职位填写成本，及时保存可能下架的职位原文，并从多个职位提炼能力、制定学习计划。延续已授权的连续制作流程。

## 本次范围

- 主入口新增整段粘贴：一段职位原文即可预览并保存；首行作为待确认岗位名，仅从明确标签提取公司、地点、薪资、来源链接。每个字段可改。多个岗位以单独一行 `---` 分隔，逐条预览并保存，显示各自成功或失败结果。
- 岗位首次导入原文作为只读快照保留，编辑描述不覆盖初始快照。旧记录首次修改时保留当时可取得的原文，不声称恢复此前丢失内容。
- 新增成长计划页面：勾选 2–10 个岗位、选择 1–12 周和每周 1–40 小时，预览将发送的档案与岗位，主动生成。模型使用已保存的兼容 chat/completions 服务配置，服务端调用，不向网页返回 Key。
- 无模型配置时可导出完整分析任务，交给 Codex Skill。Skill 生成的结构化结果通过同一 CLI 导入，网站显示同样的计划。
- 输出共同能力、涉及岗位数量、逐条原文证据、基于档案的差距说明和每周任务、交付物、验收条件。原文引用和岗位 ID 由程序核验，不能编造引用或学习链接。结果是建议，不是用户已具备的能力。
- 计划保留生成时的岗位和档案快照、来源版本与时间，不因岗位下架或后续编辑而改变。
- 本次不接自动网页抓取、插件或语音。复制内容的本地提取不发送外部请求；模型分析需用户主动确认目标服务和内容范围。

## 实施与验证

复用资料层原子写入和 CLI；新建 import.mjs、growth.mjs 负责本地解析、提示词构造及严格响应验证，网站只负责输入与展示。模型响应有大小上限和超时，禁用跳转避免 Key 随重定向外发；错误不保存成功计划或泄露 Key。

验证：批量解析和逐项失败、原始快照不变、模型引用核验、计划落盘和导出排除 Key、模拟模型 HTTP 调用和失败处理，以及浏览器导入/筛选/任务导出。没有真实用户 Key 时明确只验证模拟服务，不宣称验证所有模型服务。

## 完成交付记录

已实现粘贴批量预览、逐条归档、初始原文快照、跨岗位任务预览、兼容模型调用、引用核验、周计划与历史快照、Codex 任务导出及 CLI 计划导入。

13 项自动检查通过；浏览器验证两个岗位一次粘贴归档、选择多个岗位、任务预览与下载。模型使用临时本地模拟服务验证，没有使用真实用户 Key 调用外部服务。独立复查发现 Skill 导入旧计划可能错误关联新档案的问题，已要求 expectedContext 并补回归检查。其余边界仍按上述范围执行。
