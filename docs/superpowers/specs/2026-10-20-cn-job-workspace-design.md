# 中国本土化开源求职工作台设计

状态：用户已授权开始制作；第一阶段已实现，后续阶段尚未实现。日期：2026-10-20。

## 目标与已确认需求

将 ai-job-search 适配为中国求职者可以自行部署的求职助手。网站与 Codex 等支持 Skill 的模型工具均可使用。用户管理意向岗位、了解能力差距、亲手完成真实项目，再根据实际成果准备简历和面试。中文优先，同时支持英文自我介绍和项目表达。

用户可配置自己的模型服务与 API Key。自部署版本不向项目方支付模型调用费；模型服务商仍可能收费。未来托管版本可提供平台额度和计费，该功能单独建设。

浏览器插件支持用户主动导入当前职位。语音模拟面试是正式产品能力，不能用文字聊天冒充完成。

## 建议采用的方案与假设

建议在原仓库内新增本地网站与资料工具，复用上游工作流。只翻译 Skill 上手最快，但无法提供岗位界面与语音；直接改造为多人云平台则会过早引入账号、计费和密钥托管。选择先做单用户本地版本，再扩展托管。

首版假设：一套部署对应一个人的资料目录；通过 localhost 使用。多人隔离和公网登录属于后续托管设计，不将本地版本直接暴露到公网。岗位结构支持通用职业，项目辅导重点覆盖 AI 应用开发、AI 产品与运营，用户可选择方向。

## 仓库复用边界

- 保留 MIT 许可证与原作者声明，中文文档说明与上游的关系。
- `.claude/commands/` 和 `.claude/skills/` 继续作为工作流规范的唯一来源；本土化规则在这些规范中维护，不再复制另一套规则到网站。
- `.agents/skills/` 提供可被 Codex 发现的入口；入口引用规范并调用资料 CLI。
- 新增 `apps/web/` 提供中文网站，`tools/workspace/` 提供资料读写工具和格式定义。
- 不在安装或启动时填入虚构的个人档案，不批量改写现有英文技能。

## 阶段一：本地网站与共享资料

首个可运行交付范围：中文档案编辑、粘贴岗位描述与原始链接、岗位列表与详情、求职状态管理、模型设置，以及供 Skill 使用的同一套读写工具。

建议使用 TypeScript 网站与服务端，数据使用可直接读取的 JSON 和 Markdown 文件。首版不引入必须运行的外部数据库。具体框架和依赖版本在实施计划时依据环境确认。

默认数据目录为仓库内忽略提交的 `workspace-data/`，允许通过一个环境变量指定绝对路径。示意结构：

```text
workspace-data/
  profile.json
  jobs/<uuid>/job.json
  jobs/<uuid>/posting.md
  jobs/<uuid>/analyses/<uuid>.json
  projects/<uuid>/project.json
  projects/<uuid>/evidence/
  interviews/<uuid>/session.json
```

档案保存经历、技能和来源引用。岗位保存稳定 ID、标题、公司、地点、薪资原文、来源链接、采集时间、原始描述与申请状态。发布日期未知时保留空值。状态使用单一词表：收藏、准备中、已投递、面试中、收到 offer、已拒绝、已关闭。

资料 CLI 与网站服务端复用同一模块，支持创建、查询、更新和导出；写入采用原子替换和版本检查，冲突返回明确提示。Skill 通过 CLI 更新记录；人工改动导致格式不合法时显示文件位置与修复提示，不覆盖原始文件。所有文件路径从可信数据根目录和内部 ID 构造，拒绝任意路径输入。

岗位描述按不可信内容处理。模型不能执行其中的指令、读取本地秘密或自行调用招聘网站。职位导入首版只保存用户提供的描述及链接，不把链接误标为已取得完整正文。重复链接提示复用或更新，保留用户备注。

第一阶段验收：无需模型 Key 即可保存和重新打开档案与岗位；重启后资料保留；网站创建的岗位可由 CLI 读取，CLI 更新可由网站刷新读取；无真实 Key 也能启动；个人资料不会出现在 Git 待提交内容中。

## 阶段二：模型分析与真实项目实践

模型配置支持服务地址、模型名与 Key，先实现一种明确的 OpenAI 兼容文本协议，并如实标示不支持的能力。Key 仅由本地服务端使用，保存在单独忽略提交的设置文件中，限制文件权限；不进入日志、浏览器持久存储、资料导出和发给模型的提示词。仅展示掩码。设置入口验证连接，失败后保留已有配置。

每次分析明确展示将发送的个人资料和岗位内容范围；用户发起后才调用配置的服务。结果关联岗位和档案版本，列出匹配证据、缺口、待确认项及建议；不会把匹配结果解释成录用概率。网络或模型错误不写入成功记录；模型格式不合法的结果不能直接作为可信结构保存。

项目实践从用户背景和一个或多个目标岗位的差距生成计划。每项任务包含目标、步骤、验收条件、学习资料和预期证据。学习资料记录标题、作者或发布方、来源链接、对应任务和核查时间；未经实际查证的链接不作为已核实推荐展示。允许 Bilibili、官方手册和开源项目的外部链接，不默认复制完整课程。

学习、实践完成、成果已核对是不同状态。用户提交代码、演示、评估记录或复盘作为证据；AI 提供审核意见，最终由用户确认状态。简历草稿只引用已有证据，标明个人项目、课程项目或开源贡献，不将其描述成雇佣经历。

第二阶段验收：配置有效模型后完成一次有证据引用的岗位分析；生成关联岗位的项目计划；记录真实成果并生成与成果一致的简历项目描述；模型失败时原资料完整保留。

## 阶段三：语音面试

用户选择岗位、练习语言与面试模式，从档案和已完成项目开始问答。先支持按轮录音、转写、模型回答与语音播放，再依据使用体验评估实时打断和连续语音。文本、转写与语音合成服务分别配置，文本 Key 不默认具备语音能力。

界面明确显示麦克风状态，支持结束、重试、纠正转写及回看文字。默认只保存用户选择保留的文字记录，不永久保留原始录音；录音外发前显示目标服务。反馈引用实际回答，涵盖结构、岗位相关性与项目理解。没有音频评估能力时不生成发音评分。

第三阶段验收：完成至少三轮中文或英文语音面试并生成依据原始回答的反馈；拒绝麦克风权限、转写失败或合成失败时可继续文字练习；录音保存行为符合界面说明。

## 阶段四：插件与托管扩展

插件采用用户点击触发的当前页面读取，展示字段预览后导入配对的网站实例。只传岗位内容和来源，不传 Cookie、聊天、令牌或无关页面内容。连接本地网站需要明确配对及来源校验，不开放任意网页可写的本地接口。

招聘网站逐个检查权限与页面适配条件，不能承诺 BOSS 直聘或其他平台必然可用；遇到限制时支持手动导入，不实现绕过验证码或访问控制。只有取得真实岗位且字段可验证后才把适配标为可用。

托管版另行设计账户、租户隔离、密钥管理、计量、额度与付费。保留开源自部署使用路径，收费使用平台资源的规则独立于自带 Key。

## 实施顺序与验证原则

按阶段一到四推进，每阶段都有能实际运行的交付。下一份实施计划仅覆盖阶段一，避免把语音、插件和计费塞进同一次开发。关键验证覆盖资料往返、并发写入冲突、路径限制和敏感资料排除；界面检查覆盖新增岗位、状态变更和刷新保留。未实现阶段在界面中不伪装成可用功能。

项目最终成功标准：用户能够从真实目标岗位出发，保存自己的资料，通过网站和 Skill 连续完成分析、实践、材料准备与语音面试，并始终保留对数据与模型服务的选择。
